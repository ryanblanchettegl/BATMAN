# EWF 9000: working notes for Claude Code

Elite Wrestling Federation 9000 is a text-based wrestling booking sim for Steam, drawn as a 1990s PC program. The owner is Ryan. `NEXT.md` is the work queue: ordered steps for the next unattended run. `TASKS.md` is the task list and holds his decisions; `TWEAKS.md` is 100 small jobs and `WISHLIST.md` is 100 depth ideas, each with its own "how to work this list"; `docs/feature-list.md` is the full feature wording; `docs/design.md` is the design document; `app/DEV.md` says how screens are written.

## Commands

```
cd app && npm ci && cd ..                           # once; installs the build tools. Skip `npm install` at the root: it pulls Electron for the Steam wrapper
node build.js                                       # src/*.js -> engine.js, app/ -> dist/index.html and dist/gorilla-position.html
cd app && node_modules/.bin/tsc --noEmit -p .       # type-check the interface
node test-uni.js universes/public_domain.json 60    # headless: 60 weeks of every promotion. Want errs 0 and NaN 0.
npm run check                                       # build, type-check and a 20-week sim in one go
npm run test:browser                                # every file in app/tests, one after another (needs NODE_PATH as below)
node test-models.js                                 # 60 weeks as each company model; checks what makes it that model
node test-wording.js                                # no dice wording anywhere in 60 weeks of text
node test-determinism.js                            # same seed twice gives identical state
node test-editor.js                                 # the World Editor's engine parts: build a world from nothing, check it, play it
node test-create.js                                 # shows and belts made during a game: the occasions, the limits, and how rarely rivals add them
node test-segments.js                               # promos and angles the player books, the show clock, and how a show opens
node test-tasks.js                                  # this week's tasks, and how they hold a show and the week
node test-shape.js                                  # the running order rules, and stars instead of percentages
node test-relations.js                              # the relationship matrix, memories and the notification bar
node test-live.js                                   # the show on the air: steps, calls from the gorilla position, what each answer does
node test-first.js                                  # the opening letter, the first-year required actions, promises on the card, flags on the run sheet
node test-people.js                                 # backstage as people: who shows up and why, and what a point spent on them does
node test-fog.js                                    # fog of war: what the road agent can say, what a show teaches, the agent in your ear
node tools/build-public-domain.js                   # rebuild universes/public_domain.json after editing rosters
python3 tools/build-font.py                         # rebuild app/fonts/ewf-blocks.woff2 (needs fonttools, brotli)
```

Browser tests need Playwright with Chromium. Build first, then run from the repo root:

```
NODE_PATH=<dir containing playwright> node app/tests/<name>.js
```

`<name>` is one of `onescreen`, `start`, `office`, `booking`, `roster`, `stories`, `company`, `cards`, `journey`, `linker`, `save`, `sweep`, `challenge`, `scenarios`, `editor`, `create`, `leaveout`, `segments`, `net`, `tasks`, `shape`, `relations`, `advance`, `direction`, `calls`. A test that has to get a show from the card to its report uses `airShow(page)` from the helper (it opens the report from After the show; `toOffice(page)` goes on to the desk): there is no skipping a show on the air, and every call has to be answered (it gives the safe answer unless told otherwise). `journey.js` takes `MODES=desk,tablet,tv` and `WEEKS=5`. Each test prints its failures and exits non-zero if any. They are slow (one to five minutes each); run the ones for the section you touched, then `journey.js`.

## How the code is laid out

- `src/*.js`: the simulation. Plain ES5 in one shared closure, concatenated in file-name order by `build.js`. No screen code. State `S` is plain JSON and is the save file. A seeded generator (`rnd(S)`) makes every game repeatable. Systems plug in through hook lists declared at the top of `src/10-match.js` (`MQX`, `CRX`, `FINX`, `EFX`, `POST`, `SHOWX`, `WEEKX`, `NEWX`, `PREX`, `TASKX`).
- `src/66-relations.js`: the relationship matrix (`S.rm`) and what people remember (`S.rmY` for what they remember about the booker). It is the one place that says how two people feel about each other. Change it only through `relBump()` and `youRemember()`; read it with `relOf()`, `bondOf()`, `respOf()`, `jealOf()`. It never calls `rnd(S)`. `note(S, heading, line, kind)` puts a line on the notification bar. `docs/plans/gorilla-position.md` is the plan this belongs to.
- `src/30-show.js`, `src/31-live.js` and `app/src/screens/booking/Live.tsx`: the live show. The player's show is not worked out in one go. `E.liveBegin(S, card)` puts it on the air (`S.live`, plain data, so a save taken mid-show loads back into it), `E.liveNext(S)` runs the next promo, angle or match, and the show stops whenever the gorilla position needs a call (`{event}`) until `E.liveDecide(S, choice)` answers it. A kind of call is one entry in `LIVEK` (`pre` or `post` offers it from what is true of the next step, never a flat chance; `run` applies the answer through `relBump()`, `youRemember()`, feuds and titles). `livePlay()` runs a whole show with the safe answers, and `E.runPlayerShow` is that. Rival shows run straight through with no calls. The broadcast screen is one screen: what is on the air on the left, tonight's run sheet on the right. A show on the air cannot be skipped or left. The yellow ADVANCE button at the top right is the only way forward: it says what it will do (Ring bell, Continue, Next, Sign off, Report, Your call) and holds the focus (`liveStep()` and `liveGo()` in `screens/booking/run.ts`). The broadcast has no continue button of its own. A promo, angle or match can be skipped to its result; a call from the gorilla position can never be skipped.
- `src/34-night.js` and `app/src/screens/booking/After.tsx`: After the show, where a show ends. The sign-off does not lead to the match-by-match report. It leads to the After the show screen (`book().night`; `liveDone()`, `openNight()`, `closeNight()`, `nightFull()` in `run.ts`): the grade and the verdict, the matter the night left that needs an answer (it can be answered there), and a list of what else it left with the picked one shown beside it. The report is one press away (Match by match) and closes back to this screen. The ADVANCE button says Office: on to the desk, where Before the show is the first thing. The Office has no After the show panel; it has one button, After the show recap, that comes back. When a show goes on the air the engine notes how everybody stood (`S.live.n0`), and when it goes off the difference is filed as `rep.left`: the gate, television, who got hurt, whose mood moved, what the notification bar said, what the writers thought. `E.afterShow(S)` lays it out, trouble first. A new thing a show should leave behind is one more `add()` in `E.afterShow`. A show can also leave one matter in the inbox that has to be answered (`nightMatter()`: a hurt champion, somebody furious, an act that caught fire, the match of the night with no story); a new one is one more case there and an `EVR` entry.
- `src/32-direction.js`: the calls that set the direction of the company. The owner on the headset (the office wants its favourite to win: do as told, refuse, or find a way round). Who the show is built around (`S.fc = {id, w}`, decided on the air after a main event; read it with `faceOf(S)` or `E.faceInfo(S)`). The crowd comes to see the face of the company: a lift to the show's hype when they are in the main event, a letdown when they could be on the card and are not (`faceHype()`, and a warning from `E.validate`), and louder matches. The network on the line (what is going out is more than the slot was sold as; the answers move the network's patience, `S.clocks.net`). The sponsor at ringside (a deal with four weeks or fewer left wants its name on the main event). A new call of this kind is one more entry in `LIVEK` here, added to `LIVE_ORDER` (before a segment) or `LIVE_POST` (after one).
- `src/33-ring.js`: three calls caused by the match in the ring. Somebody is hurt (a worn body in a demanding match; the answers are the old headset's bad landing, through `E.resolveChaos`). The crowd has gone quiet (the match before fell flat: stay, take it to the floor, the villain cheats, or call the upset). They are not going home (two who work well together, a hot feud or creative control: take it home, or give them the time and cut a segment, shorten the main event or run over the slot). The order every kind is tried in is `LIVE_ORDER`, set at the end of this file.
- `src/79-people.js` and `Backstage` in `app/src/screens/office/BeforeShow.tsx`: Backstage is its own page in the Office (the desk has one line about it and a button). It is people, not rooms. Seven rooms: Your office first (the old production truck, id `truck`: people come to the booker's door about their story), catering, the trainer's room, the gym, the parking lot, the owner's office, wrestlers' court. Nobody is in a room by chance: `peopleNow(S)` puts each person in the room their reason belongs to (hurt or worn down in the trainer's room; furious, low, real heat or the owner's favourite in catering; a rival's offer, a contract running down or an ambush in the parking lot; the breakout pick, an act the crowd is with or two rivals who do not click in the gym; a rivalry's next chapter, the champion, a newcomer or the face of the company in the truck). It only reads the game. One action point is spent on a person, once a week each (`E.peopleDo`, `S.apWho`), and what it does is an entry in `PPL_ACT`, through `relBump()` and `youRemember()`. A matter the last show left on the desk can be answered there (sitting down with somebody furious closes it). A new reason is one more block in `peopleNow()`. The rooms' own actions (the owner, the court, the class, the pep talk, the truck) are still under "Around the building", one visit to each a week.
- `src/98-plot.js` and `Plot` in `app/src/screens/stories/Storylines.tsx`: booking power spent on the Storylines page. Three entries in `PLOT`: break up a tag team (2), push a wrestler (2, once in eight weeks each), buy a budget pre-tape (1). A pre-tape is an ordinary segment on the next show's run sheet marked `tape: 1`, placed at the start, the middle or the end, and a suggested card keeps it. `E.plotInfo(S)`, `E.plotDo(S, id, o)`. A new thing booking power buys there is one more entry.
- The rooms' own actions backstage (`E.apDo`) are buttons under "Things to do" on the Backstage page. Each opens a pop-up (`ActWindow`, modal kind `apact`) that says what it does, asks who, and spends the point. There is no menu of rooms.
- `src/78-models.js`: the nine company models. Each is data plus small functions for match quality, crowd, finishes, pushes, hiring fit and the suggested card.
- `app/src/`: the interface in Preact and TypeScript. `store.ts` holds the game and view state, `nav.ts` the screen map, `input.ts` screen modes and remote or gamepad focus, `kit/` the building blocks, `screens/<section>/` one folder per section, `shared/` pieces used by more than one section.
- `src/86-editor.js` and `app/src/screens/editor/`: the World Editor, opened from the title screen. It edits a universe package (plain JSON kept with the player's other worlds), never a running game. Every change goes through an `E.ed*` function so it can be tested headless.
- `src/87-create.js` and `app/src/screens/manage/Create.tsx`: belts and weekly shows made during a game. These are big moments, not yearly habits, and they follow real-life precedent: each takes an occasion (`beltOccasions()`, `showOccasions()`), a company adds one belt a year and one show in two at most, and rivals add them rarely, one at a time, only for something that has come about since the game began (`rivalGrow()`, once a year in each rival's own month; `S.mkw` spaces them across the world). `P.mk` is where a company stood, `P.grown` its record. A new occasion is one more entry in those two functions. A new show scales the company's overheads the way `calibrateCosts()` did for the shows it started with, and copies the main show's crowd expectations.
- `src/88-shows.js`: a weekly show lasts. Every show of every company carries its years on the air (`sh.on`, `sh.ep`), a standing from 0 to 100 that is only ever said in words (`sh.pr`, `airWord()`: Brand new, Finding its feet, Established, A fixture, Appointment viewing, An institution), a network and its size (`sh.net`, `sh.tier`) and the week its deal is up (`sh.deal`). Standing moves a little with every episode (beating what the crowd expected, a growing audience, a point on each anniversary) and brings viewers, measured against where the show began (`airPF()`), so a new game starts where the calibration put it. When a deal is up the player answers it in the inbox (`rights`: stay, move, hold out) and a rival settles its own. A show is never cancelled by a rival: it moves to a smaller network (`airDemote()`). An anniversary or a milestone episode is an occasion (`airNight()`). Nothing here locks a new show or belt in a booker's first years.
- `src/92-shape.js` and `app/src/screens/booking/Shape.tsx`: the running order. Where a match sits on the card changes how it lands (opener, back-to-back, main event, finishes across the night). `E.shape(S, card)` reads a card before the show; `shapeAuto()` lays out automatic cards by the same rules.
- `src/93-segments.js` and `app/src/screens/booking/Segments.tsx`: promos and angles the player books on the run sheet. There is no fixed number of them. Each is short, medium or long (5, 10 or 15 minutes). The kind `writers` hands that time to the writers (`genAngle`); the writers add nothing on their own.
- `src/97-time.js`: time is the budget. A show is two hours of weekly television or three of big event, and the run sheet has to fill it (`E.clock(S)`, `E.matchMins()`, `E.fitShow()`). More than five minutes over, or more than ten empty, and the show cannot run. The first thing on the sheet opens the show, and each way of opening pays in its own way; whatever is on the air at the top of each hour is judged against what the crowd expects. `E.suggest(S)` returns a whole show that fits, and sets the promos and angles as it goes. Anything that books without a person must call `E.fitShow(S, card)` after changing a card. Only the player's shows are on the clock.
- `src/99-fog.js`: fog of war. The game does not say how a match or a promo will go. The road agent comments on every match on the sheet (`E.agentReads(S)`), and only says what can be seen, what the office has seen on its own shows (`S.know`: pairings, who blows up, who has been heard on the microphone), or what the agent can read. A better agent, an agent put on the match, and the booker's Eye for talent and level all make a read more likely. A read is never wrong; a weaker agent just says less. Promos and angles get a read in words (`look.read`), not a forecast in stars. During the broadcast the agent speaks in the booker's ear (beats of type `ear`), and the report lists what was learned (`rep.learned`). A new thing the player should have to learn goes here: hide it before the bell, name it in the ear, and add it to what the night teaches.
- `src/94-net.js` and `app/src/screens/net/`: the Net section (dirt sheet, the feed, the boards). It reads the game and never uses `rnd(S)`; lines are picked with `h01()`, so a post can never change how a game plays out.
- `src/95-tasks.js` and `app/src/screens/office/Tasks.tsx`: this week's tasks on the desk. A task is answered in a pop-up on the desk where it can be, so the player does not have to leave the Office (`VoicesWindow` in `screens/office/Windows.tsx`, the commentary desk, is the first; the rest still lead to their page). The engine lists them and answers `E.taskGate(S, 'book' | 'show' | 'week')`; the screens do the stopping, so headless games never wait. A new thing the player should fill in each week gets a task: push a function onto `TASKX`.
- `src/96-first.js`: the first year, and how a game opens. `E.welcome(S)` is the owner's letter a new game opens on (`WelcomeWindow`; shown with the start-up screens, so tests skip it with `boot: false`). Required actions are tasks with `req: true` and `waive: false`, asked once (`S.req`): a sponsor after the first show (in `src/95-tasks.js`), the face of the company before the first big event (`E.faceCandidates`, `E.nameFace`, the `FaceWindow` pop-up on the desk). A new required action goes here.
- The run sheet shows the risk on every line: `E.cardFlags(S)` at the end of `src/99-fog.js` gives each match short flags (Worn down, No chemistry, Chemistry, Too long, Unhappy, Promised a win, Promise kept). A flag about the ring never says more than the agent's read. The same file makes `E.validate` warn about a promised win about to fall due, and makes `E.suggest` call promised wins it can pay for and put the face of the company in the main event.
- The desk opens on the fire: open inbox matters are at the top of Before the show (`Fire` in `screens/office/BeforeShow.tsx`), above the tasks. The panel lower down holds what has been answered.
- `src/96-advance.js` and `app/src/shell/Advance.tsx`: the ADVANCE button (laid over the right end of the menu bar, yellow, one or two words). `E.advance(S)` says what the week needs next and only reads the game; the screen draws it and presses the right thing. When tasks are in the way it says Attention and leads to the desk. `E.comingUp(S)` is the desk's countdown line. A new step in the week, or a new countdown, goes there. `docs/plans/advance-button.md` says why it is built this way.
- `app/addons/*.js`: self-contained scripts appended to the page as they are (the soundtrack).
- `universes/public_domain.json`: the default world, generated by `tools/build-public-domain.js` plus `tools/pd-extra.js`.
- `legacy/`: the old interface. Nothing builds it.

## Rules

1. **The engine owns the game.** A screen never writes to `S`. It calls `E.something(S, ...)` inside `act()` and redraws.
2. **Zero external assets.** No hosted images, fonts, scripts or styles. Borders, bevels and scanlines are CSS; charts and room art are text; portraits are drawn on a canvas by code; the fonts are embedded as base64.
3. **Original content only.** Models and storylines may follow how real companies and angles worked. Game content never names a real promotion, wrestler, stable, title or event. The default universe is public domain: people who died before 1926, myth and folklore, or fiction published before 1929 by an author who died before 1955. No figures still honoured in a living religion. No real-world rosters in this repository.
4. **No dice wording.** Checks are "attempts" with a percentage chance and a list of what helps and what hurts.
5. **Four inputs.** Every control is a real button, select or input, reachable by mouse, touch, keyboard and remote or gamepad. Nothing depends on hover. Give each control a `data-t` name; the tests find controls that way.
5. (continued) **No phone, no portrait.** The game is for a wide screen: desk, tablet and TV. There is no phone layout and no phone test run. A tall narrow window shows one line asking for a wide one. Do not add narrow-screen layout rules.
5a. **Where things sit.** Top: the menu bar, unchanged in height and look, with the yellow ADVANCE button laid over its right end, and the notification bar under it. Bottom: the status line only, with Options, Help and Music at its right end. Tasks live on the desk, nowhere else. Nothing else goes in those bars.
5b. **One screen, no scrolling.** Ryan wants every page to fit the window with nothing to scroll. A page that has been converted wraps itself in `.onescreen` (styles at the end of `app/styles/booking.css`): the frame becomes exactly one window tall and the page's parts share the height. On a one-screen page type is sized from the window's height as well as its width (`--fs` in `base.css`, the `:has(.onescreen)` rules), so about 29 lines always fit; pages that still scroll keep the old sizes until they are converted. The pattern is a compact list on the left, one line an item, and a pane on the right that shows whatever is selected, or a tab of notes when nothing is. A list that can outgrow its box turns pages (`Paged` in `screens/booking/Side.tsx`); it never scrolls. Test with `fits(page)` from `app/tests/helper.js` and `app/tests/onescreen.js`, at 1280x720 as well as larger. Converted so far: the card builder, the broadcast, After the show. Do not add a page, a panel or a block of text to a converted page without checking it still fits. Pages not yet converted still scroll; convert them one at a time, with Ryan's go-ahead for each.
6. **Six sections:** Office (The desk, Backstage, Storylines, Career), Booking, Roster (Roster, Locker room, Titles, Free agents), Net (Dirt sheet, The feed, The boards), Manage (Operations, House, Deals), Company (Overview, Finances, World, History). The desk, Backstage and Storylines are the main tabs of the Office (Ryan, 6 October); there is no Stories section any more. Net is information only, like Company. Manage holds every choice; Company is information only; the desk opens on "Before the show".
7. **Readable first.** Ryan's design goal is the pull of "one more turn" with screens that are easy to read and quick to act on. Every action shows its result at once. Prefer a pop-up or a short note to another panel.
7a. **No clean stopping point.** Office, Booking and the Show each hand the next one something unresolved (`docs/design.md`, section 2a, in Ryan's words). The week opens on a fire with a deadline. Booking is a risk and reward puzzle where chemistry, morale and fatigue are limits the player can see. The Show pays out and ends on a new problem or chance for next week. A feature that ends a phase on a clean slate is not finished: say what it hands to the next phase.
8. **Plain writing in the game and in docs.** Short sentences, no jargon, no em dashes in new text.
8a. **Stars, not percentages.** Stars are for after the bell: nothing is forecast in stars before a show (see `src/99-fog.js`). How good a match, promo or angle was is shown as stars (`stars()` in the kit, `starG()` in the engine), never as a number. A target about a match is worded in stars and checked with `starMeets()`. Chances stay percentages (rule 4).
8c. **A show is a letter grade and a word.** The show's own score is shown as a letter grade only (`grade()` in the kit, `gradeG()` in the engine), never as a percentage. A target about a show is worded as a grade and checked with `gradeMeets()`. What a crowd expects is never shown as a number. It is said on the ladder in `src/98-words.js` (a bomb, a dud, flat, decent, solid, strong, hot, red hot, blow-away, all-time classic): `E.expectWords(S)`, `E.showWord(v)`. Each rung lines up with a grade. How a show did against its crowd is `E.showVerdict(rating, exp)`: a headline ("Blew the roof off", "Came up short") and one line. New text about a show uses these, not a made-up phrase.
8b. **Money:** short form (`cash()`, `$1.2M`) in tables and lists; full form (`full()`, `$1,200,000`) for a single headline figure.
9. **Saves:** the save is `S` under the key `ewf9000-save-4`. A change that breaks old saves needs a version bump and a migration.
9a. **One step at a time.** Do one step, show Ryan the result, and wait for his go-ahead before the next. Do not run batches side by side.
9b. **Relationships are the centre.** A new decision or event says what it does to the people involved through `relBump()` and `youRemember()`, so they remember it and the notification bar reports it.
10. **Commits:** small, with a message that says what changed for the player. Tick the boxes in `TASKS.md` in the same commit.
10a. **Versions:** from 6 October, at least five changes go into a version before its number moves (`VER` in `app/src/store.ts`). Commit each change as it is done; bump the number once five or more are in.

## Things that bite

- `build.js` must run before any test; the tests open `dist/index.html` and `engine.js`.
- `calibrate()` in `src/00-core.js` runs sample shows for every promotion at the start of a game to set crowd expectations. A change to match scoring moves expectations with it, so compare "rating minus expectation", not raw ratings.
- The typeface (VT323) has no box-drawing, block or shape characters. They come from the generated font `EWF Blocks`. A new symbol in the interface needs adding to `tools/build-font.py`.
- A game year is 48 weeks: twelve months of four weeks (`cal()` in `src/00-core.js`). Yearly things use 48, not 52.
- Preact needs keys on lists whose items change shape between redraws.
- Browser tests start with this week's tasks as reminders only (`helper.open()` calls `E.setGate(S, false)`). Pass `gate: true` to test the stopping.
- The headless sim never signs anyone, so its rosters shrink over time. That is the sim, not the game.
- A call on the broadcast takes no answer for its first 400 ms, so a press meant for Continue cannot answer it. Browser tests wait before they pick.
- While a show is on the air the report is `S.live.st.rep`, not `S.reports[0]`. It is filed when the show goes off the air.
- A call waits out its own time before it can come up again (`S.lcd`, weeks by kind or by person). A test that wants a call sets up its cause and clears `S.lcd`; `app/tests/calls.js` shows how.
